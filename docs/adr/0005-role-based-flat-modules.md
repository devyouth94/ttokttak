# 역할 중심 평면 모듈

## 맥락

FSD 계층에서는 하나의 실행 흐름이 `screens`, `features`, `entities`와 `shared`를 차례로 통과했다.
전달 파일과 공개 진입점이 늘어 화면에서 외부 경계까지 추적하기 어려웠다.

## 결정

코드는 화면 소유권과 제품 역할을 기준으로 배치한다.

- route와 페이지는 `app/`에 둔다.
- 한 화면이 소유하는 코드는 `src/screens/<화면>/`에 둔다.
- 공유 코드는 `schedule`, `session`, `account`, `notifications`, `theme`, `sentry`처럼 제품 역할 이름으로 둔다.
- 전달만 하는 배럴, 호환 wrapper와 계층별 공개 진입점을 만들지 않는다.
- 하위 디렉터리는 독립된 역할이 있을 때만 만든다.

## 결과

페이지에서 화면 로직과 외부 경계까지의 의존 단계가 짧아진다.
구조 규칙보다 실제 소유권을 판단해야 하므로 배치 기준은 [`SYSTEM_DESIGN.md`](../SYSTEM_DESIGN.md)에 유지한다.

## 검토한 대안

- FSD 유지: 일관된 계층 대신 전달 단계가 계속 남아 제외했다.
- FSD 배럴만 축소: 파일 수는 줄지만 계층별 책임은 남아 제외했다.
- 역할 중심 평면 모듈: 별도 아키텍처 프레임워크 없이 현재 앱 규모에 맞아 선택했다.
