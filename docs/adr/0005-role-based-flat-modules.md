# 역할 중심 평면 모듈

Ttokttak은 FSD 계층 대신 화면 소유 경계와 제품 역할을 기준으로 코드를 배치한다. 계층별 전달 파일을 따라가야 했던 구조를 줄이고, 화면에서 외부 경계까지의 실행 흐름을 짧게 읽기 위해 이 구조를 선택한다.

**Considered Options**

- FSD 계층 유지: import 규칙은 명확하지만 하나의 흐름이 `screens`, `features`, `entities`, `shared`를 차례로 통과한다.
- FSD 안에서 배럴과 공개 진입점만 줄이기: 파일 수는 줄지만 계층별 책임과 전달 단계는 남는다.
- 역할 중심 평면 모듈: 별도 아키텍처 프레임워크 없이 화면 소유권과 제품 역할을 코드 위치에 직접 드러낸다.

**Consequences**

- 루트 `app/`에는 Expo Router route와 페이지 컴포넌트만 둔다.
- 한 화면이 소유하는 코드는 `src/screens/<화면>/`에 둔다. 조회, 상태와 동작은 화면 루트에 두고 렌더링 파일은 `ui/`에 둔다.
- 여러 화면이나 앱 전체가 공유하는 코드는 `schedule/`, `session/`, `account/`, `notifications/`, `theme/`, `sentry/`처럼 제품 역할 이름으로 둔다.
- 한 파일이면 `i18n.ts`, `supabase.ts`처럼 `src/`에 직접 둔다.
- `features/`, `entities/`, `shared/`, 반복되는 `model/`, `hooks/` 계층은 최종 구조에서 사용하지 않는다.
- 전달만 하는 배럴, 호환 wrapper와 `v2` 구조를 만들지 않는다. 필요한 파일을 직접 import한다.
- 하위 디렉터리는 파일 수가 아니라 독립된 역할을 드러낼 때만 만든다. 현재 일정 모듈은 `content/`, `db/`, `display/`, `rules/`, `ui/`를 사용한다.
- 기존 구조는 페이지별 실행 흐름을 새 위치로 교체한 뒤 같은 작업에서 삭제한다. 전환 중 남은 기존 디렉터리는 새 코드의 기준으로 사용하지 않는다.
- 구조 전환은 사용자 동작, 저장 데이터, 개인정보 경계와 UI를 바꾸지 않는다.
