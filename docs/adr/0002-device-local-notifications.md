# 기기 로컬 알림

## 맥락

일정 제목과 설명은 개인 생활 패턴을 드러낼 수 있다.
알림 신뢰도보다 서버와 push provider가 표시 내용을 알지 못하는 경계를 우선한다.

## 결정

일정 알림은 기기 로컬 알림을 기본 경로로 사용한다.
알림 tap은 occurrence 처리 화면인 홈으로 이동한다.

## 결과

- 현재 기기가 일정 데이터에서 예약 상태를 다시 계산한다.
- 예약을 바꾼 뒤 OS 목록을 다시 읽어 부분 적용 여부를 확인한다.
- 알림 동기화 진단은 최근 성공과 실패를 현재 기기에 각각 한 건만 보관한다.
- 기기 상태, 권한과 OS 정책에 따라 알림이 지연되거나 표시되지 않을 수 있다.
- OS의 실제 알림 표시 여부는 확인하거나 기록할 수 없다.
- 원격 푸시용 server, token과 inbox를 운영하지 않는다.

성공 진단에는 시각, 후보 수와 예약 수를 저장한다.
실패 진단에는 시각과 실패 단계만 저장한다.
권한은 설정 화면에서 현재 상태를 별도로 보여준다.
사용자·일정·알림 식별자와 원본 오류 메시지는 저장하지 않는다.
로그아웃이나 실행 중 계정 변경 때 알림 동기화 진단을 삭제한다.

Sentry에는 호출 계기와 허용 목록에 있는 실패 단계·내부 오류 코드만 추가한다.
알림 표시 내용과 식별자는 전송하지 않는다.

## 검토한 대안

원격 푸시는 신뢰도 보완이 실제로 필요해질 때만 일반 문구 fallback으로 다시 검토한다.
그 경우에도 일정 제목과 설명은 payload에 넣지 않는다.
